# 运维体系：巡检、台账、回退与事故恢复

防护不是一次性施工，是持续运维。本节定义四件套：每日自动巡检、信号台账、回退纪律、事故恢复顺序。

## 每日巡检

`scripts/daily-signal-scan.py`（纯标准库，基线全部环境变量注入，零硬编码）部署为每日定时任务，cron 避开整点/半点（建议 7-23 或 37-53 分）。哨兵清单随版本演进，以脚本为唯一准；当前覆盖：

| 哨兵 | 判定 | 防什么 |
|---|---|---|
| TUN 接管 | 活动适配器含隧道 | 网关死亡第一信号 |
| 出口 IP（ipify） | =基线住宅 IP | 出口漂移 |
| Cloudflare trace | 国家=基线国 | 链路层画像 |
| 出口归属（ipinfo） | 国家=基线国 | 二手验证 |
| WebRTC STUN | 仅见基线 IP | STUN 泄漏回归 |
| IPv6 出口 | 获取失败 | v6 泄漏面回归 |
| DNS 解析一致性 | 系统解析与 Cloudflare 一致 | 劫持失效/投毒回归 |
| ipleak DNS 泄漏 | 解析器全在 CF/Google/Quad9 白名单段 | **本地网关劫持 UDP53 上送运营商递归**（v1.38 型事故的唯一可靠自动哨兵） |
| 配置完整性 | DoH nameserver / dns-hijack / MATCH 兜底在位 | 客户端升级回写配置 |
| IP 直连白名单快照 | 必需条目在位 + 已清除条目未回潮 | 直连通道漂移 |
| DNS 核心健康 | 双路应答 | DNS 半死（表现为"部分网站打不开"） |
| 系统信号 | 时区/MachineGuid/区域格式=基线 | 系统层漂移 |
| Killswitch 漂移 | 防火墙规则路径=应用实际安装路径 | 商店应用自动更新换路径 |
| 检测站可达性 | 9 站 HTTP 200（WARN 不计 FAIL） | 检测面本身可用性 |

报告 PASS/WARN/FAIL 落盘 `workspace/reports/daily-signal-scan-<date>.md`，FAIL 当天处理。检测站深度项（需浏览器交互）列人工复核清单，每周手动过一遍。

## 信号台账

`signal-ledger.md`（或等效文件）：每次改动的"为什么改、怎么验证、残余面是什么"。格式一条版本记录 = 背景/处置/验证/待办。它的读者是三个月后的自己——"忘了为什么"时查它，而不是重新试错。台账同时承担缺口清单职责（见 capability-gaps.md）。

## 回退纪律（每个改动阶段的强制前置）

1. 动手前写该阶段的回退脚本并**实测可运行**；
2. 预估可能断网的步骤，设立"超时未确认则自动回退"防线（脚本带超时参数，无人确认自动执行回退）；
3. 配置备份一律时间戳命名，与回退脚本同目录；
4. 系统级事故优先级高于一切隐私目标——宁可防护缺席一天，不可把机器改到要重装系统。

## 事故恢复顺序

改 DNS/分流配置后失联时按序执行，每步后实测联网：

1. 关链式代理（若启用）。
2. 关 TUN，退回系统代理模式。
3. 核验 nameserver 是否被客户端覆写漂移。
4. 仍不通：重启网关；再不通：用最近一份备份恢复配置后重启。
5. 验收基线：**用户本机正在使用的 AI 客户端能在 TUN 下正常对话 = 网络层验收通过的最高优先级项。**

## 升级与漂移核验

代理客户端、内核、浏览器的大版本升级是漂移最大来源。升级后必做"四键核验"：

1. 链式激活态在不在（自建网关查 relay 组选中项；GUI 客户端查链式开关非空）？
2. 规则与编辑基线一致（进程白名单在位、MATCH 兜底位置、隔离区未被唤醒）？
3. 出口 IP 实测走住宅链而非裸节点？
4. DNS 口径（DoH nameserver / fake-ip / TUN / find-process / IPv6 双关）？

## 双开处置

同一网关联跑两个实例 = 端口互抢 + 静默半死（新实例抢不到端口照常运行但无 TUN/无面板，"看似在保护其实没有"）。纪律：启动脚本幂等（已运行则跳过）；发现双开时杀掉全部实例再以提权方式单实例启动（TUN 创建需要管理员）；面板 404 或出口漂移是双开的典型症状。

## 检测站与通过标准

执行层面的站点清单以 `scripts/daily-signal-scan.py` 的 SITES 为唯一执行源；本表是各站的通过标准与人工复核口径，新增/下线检测站时两处同步改。

| 站点 | 看什么 | 通过标准 |
|---|---|---|
| `ip.net.coffee/claude/` | 目标 AI 服务视角的整体风险面 | 过关项全绿；语言/时区/IP 信号不命中真实所在地 |
| `ip.net.coffee/dns/`（深度测试） | DNS 泄漏 | 中国 DNS 条目清零。**测前必须确认 TUN 已开启**，否则本地网络直连会误报 |
| `ip.net.coffee/webrtc/` | WebRTC 泄漏 | 只显示出口 IP，无本地/真实公网 IP |
| `ip.net.coffee/cloudflare/` | CF 校验 | 能过 CF 校验页（住宅 IP 基本要求） |
| `iplark.com` | C 段画像/AI 检测/代理检测/IPv6 | AI 检测与代理检测"检测失败"；IPv6 出口"获取失败" |
| `ippure.com` | 人机占比 | 人类流量占比高 |
| `ippure.com/claude.html` | Claude 专项面 | 风险分低于站点阈值；语言/字体信号不命中 |
| `ippure.com/DNS-Leak-Detect.html` | DNS 泄漏专项 | 每次必测：中国条目清零 |
| `ipleak.net`（dnsdetection API/网页版） | DNS 解析器名单 | 全部落在 CF/Google/Quad9 白名单段（巡检哨兵每日自动测） |
| `scamalytics.com` | 欺诈分 | Fraud Score 低 |
| `cc.mastersgo.cc` | 过关清单 | 未过关项逐条处置 |

**每周人工复核**（脚本替代不了）：DNS 深度测试、claude 过关项逐条、iplark 三指标、过关清单未过项。结果记台账。
**月度**：GitHub commit 搜索旧邮箱变体 total=0；邮箱泄露库复核（方法见 account-metadata.md §3）。

## 运维纪律（十三条）

1. 改库先备份（时间戳后缀）→ 重启 → 核验生成配置 → 端到端实测。四步缺一不算完成。
2. 以生成配置为准，不以 UI 或数据库行数为准（GUI 客户端渲染存在启用/停用双行与跨 profile 行）。
3. 规则只增不滥：新增直连白名单必须标注归属与用途；定期按"日志零命中+归属核验"清理（IP 规则用 ipinfo 类服务核归属，境外 IP 直连=对方可见真实出口，优先清除）。
4. 失联恢复顺序见本文件"事故恢复顺序"节。
5. 历史中间文件按白名单清理：只留文档台账、在役脚本、每系列最新一份配置备份；清理明细留日志文件。
6. 巡检报告与信号台账是持续运维载体——新增/关闭任何信号面的处置都记台账变更记录（版本号+日期+证据）。
7. 卸载任何软件后，立即审计其计划任务/启动项/驱动残留（卸载程序普遍不自净）。排查法：`Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-TaskScheduler/Operational'; StartTime=<近2小时>}`，触发间隔异常（如每 2 分钟）的自家任务是重点怀疑对象。
8. 注册表写入必须二次读取校验（写入与读回值一致才算完成）。曾发生"轮换 MachineGuid 以为成功、数日后核查仍为旧值"的案例——不校验的写入等于没做。
9. 系统重装/恢复后，HKCU 下的隐私策略（如 Chrome WebRtcIPHandling、locale）全部归零，须在巡检中重验并补写；把"重装后首巡"当作一次全新部署对待。
10. 新装目标应用后审计其配置目录（如 Electron 应用的 `%APPDATA%\<App>\config.json`）：登录态、分析设备 ID（ant-did 类）、遥测计划任务。账号绑定前的窗口是调整画像的唯一时机。
11. 共享运行时白名单必须用 PROCESS-PATH（完整路径）而非 PROCESS-NAME：node.exe/python.exe 是所有 Node/Python 程序的共用进程名，按名字放行=把同机所有 CLI 工具放出隧道。精确路径白名单与"全局 node 落兜底 MATCH"即为正确隔离形态。
12. 区域格式（Culture/LocaleName，决定货币符号/日期格式）是 IP↔locale↔currency 一致性轴的一部分，必须与出口国对齐；显示语言可独立保持母语。
13. killswitch 防火墙规则先于"代理永远在线"的假设落地：先写回退脚本并实测可运行，再装规则；安装后必须端到端验证两种状态（代理在线=应用正常、代理全关=连接失败而非连通）。

## 基线管理

| 环境变量 | 用途 | 未设置时 |
|---|---|---|
| `SIGNAL_BASELINE_IP` | 住宅出口基线（必填） | 巡检该项报 WARN 并提示配置 |
| `SIGNAL_MACHINE_GUID` / `SIGNAL_OLD_GUID` | MachineGuid 基线/旧值回潮检测 | 该项只记录不判定 |
| `SIGNAL_KILLSWITCH` | JSON：防火墙规则名→应用包/exe 映射 | killswitch 哨兵跳过 |
| `DOMESTIC_DNS_IP` | 国内引导 DNS | 默认 223.5.5.5 |
| `CLIENT_CONFIG_YAML` | 客户端生成配置路径 | 配置哨兵跳过 |
| `REQUIRED_DIRECT` / `FORBIDDEN_DIRECT` | 分号分隔的必需直连/已清除回潮条目 | 快照哨兵跳过 |
| `SIGNAL_CULTURE` | 区域格式基线 | 默认 ja-JP |

基线变更（换节点/IP）流程：新基线实测达标（见检测站表全套）→ 更新环境变量 → 当日巡检确认 PASS。
