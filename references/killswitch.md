# Killswitch：误关代理时的 fail-closed 兜底

隧道方案的隐含假设是"代理永远在线"。人为失误（手滑关掉网关/TUN/系统代理）会让被保护应用落入唯一危险形态：无接管层 → 真实 IP 直连目标服务。per-app 防火墙规则把这一形态从"靠纪律"变成"系统强制不可能"。

## 桌面端规则结构

```text
AI 客户端 exe ─出站─→ 防火墙规则 ─┬─ 目的=127.0.0.1        → 放行（系统代理路径）
                                ├─ 目的=198.18.0.0/15   → 放行（TUN fake-ip 路径）
                                └─ 其余全部 IPv4 + 全部 IPv6 → 拒绝（代理全关时只报"连不上"）
```

要点：

1. **放行段只有两段**：回环（防火墙对回环默认豁免，无需显式放行）与 fake-ip 段。TUN-only 模式（系统代理关）下应用直连 fake-ip，必须在放行集内，否则 killswitch 误伤正常代理使用。
2. **`-Program` 不支持中段通配符**（仅尾通配）；MSIX 商店应用（Claude/ChatGPT 桌面端均属此类）版本目录随自动更新变化，规则必须填精确路径，并接受"更新即漂移"的维护模型。
3. **版本漂移由巡检哨兵兜住**（规则程序路径 vs `Get-AppxPackage` 安装位置逐日比对，mismatch 即 FAIL 并重跑安装脚本刷新）。实战：Claude 桌面端约两周自动更新一次，漂移真实发生。
4. **回退脚本先行**：安装前先写 `killswitch-rollback.ps1`（删除规则即恢复），并实测一次回退可运行。
5. 已知边界：LAN（192.168/10.x）对目标应用同样被禁（本机 MCP/走 localhost 的服务不受影响）；覆盖清单外的同类应用需各补一条规则。
6. 执行：提权运行 `scripts/killswitch-install.ps1`（先按目标环境填 `$targets`），回读 `Get-NetFirewallApplicationFilter` 验证路径生效；端到端验收 = 代理在线时应用正常 + 代理全关时应用报连接失败而非连通。

## 浏览器变体：防火墙机制

浏览器侧的角色划分（代理浏览器/国内直连专用、新装浏览器二选一）是浏览器层的纪律，见 `browser-telemetry.md` §0；本文只覆盖防火墙机制本身。

- 覆盖侧放行集在桌面端基础上**额外放行内网三段**（`10/8`、`172.16/12`、`192.168/16`）：校园网/企业认证页、路由器后台、局域网服务必须可达，否则认证流程本身被掐死。
- Chrome 路径 `Application\chrome.exe` 稳定，无版本目录漂移，**无需哨兵**。
- 封锁段枚举（除回环/fake-ip/内网外的全部 IPv4 + 全部 IPv6）：`0.0.0.0-9.255.255.255`、`11.0.0.0-172.15.255.255`、`172.32.0.0-192.167.255.255`、`192.169.0.0-198.17.255.255`、`198.20.0.0-255.255.255.255`、`::-ffff:ffff:ffff:ffff:ffff:ffff:ffff:ffff`。
- 回环豁免是 WFP 层行为（规则文本覆盖 127/8 也无妨，实测代理在线时浏览器经回环代理端口正常上网）。
- 验证要点：地址段校验（白名单 IP 不在任何封锁段内、公网 IP 在）+ 代理在线时 headless 实测可出网。
- 直连专用侧在网关规则中的实现（进程 DIRECT 规则的位置与语义）见 `network-gateway.md` 五相位表。

## 设计语义备忘

- killswitch 是**独立兜底层**，不属于任何代理网关：网关在线时它完全无感（流量走放行段），网关死亡时它接管判决。换网关、换节点、换端口都不影响它——防火墙只约束目的地址，不约束回环端口。
- killswitch 名单是**有意识的最小集**：名单内的应用"宁断不漏"，名单外的应用依赖"TUN 常开"纪律。给应用加 killswitch 的判据 = "该应用裸连一次的伤害 >> 它暂时连不上的不便"。
