# 能力边界与诚实缺口

防护体系的上限由架构决定，不由努力决定。本节列出"做不到/不防"的完整清单——使用者有权知道墙壁在哪，假装闭合比承认残留更危险。每条缺口标注其缓解手段（若有）与接受理由。

## 一、结构性缺口（单方面不可消除）

| 缺口 | 说明 | 缓解 |
|---|---|---|
| **代理服务商侧知情** | 住宅 IP 提供商、机场/中转商在协议层知道你的真实连接来源。买代理=把信任转移给供应商，不是消除信任 | 选口碑商家；链式（入口不知出口内容）；支付渠道不绑真实身份；接受为体系基石 |
| **本地网络运营者知情** | 校园网/运营商知道"这个 IP 在大量加密流量发往某境外服务器"。看不到内容，但看得到模式（流量特征、时段、对端） | 流量形态贴近普通用户（不全天满速）；接受——只要内容加密，模式信号的定位价值有限 |
| **账号强绑定资料** | 手机号、支付卡 BIN、实名认证是服务商侧数据，网络层无法干预 | 虚拟卡/礼品卡降低关联；注册资料与掩护画像一致；接受为使用服务的对价 |
| **服务商侧行为聚合** | KYC、设备-账号关系图谱、行为速率、外部威胁情报、人工复核标签——对方服务端的数据单方面不可消除 | 使用习惯管理（速率、时段、不跨身份复用行为模式）；接受 |
| **国内人设面的定位精度** | 国内域名直连暴露"此人在中国"。任何未被进程规则/killswitch 覆盖的软件都能得出这一结论 | 这是主动保留的掩护身份的一部分——"在中国"是低精度信号，城市/楼栋级信号已被网络层掐断 |

## 二、采集面缺口（读得到，但读到的不是真相）

| 缺口 | 说明 | 缓解 |
|---|---|---|
| 已安装软件列表/进程列表 | 本地 API 无门槛可读，网络层管不到"读" | 采集结果本身不直接定位；高危进程的外发已被网络层/killswitch 约束 |
| WiFi 邻近 SSID | 本地读取无法系统级阻止 | 阻断"外发"（进程网络白名单）；SSID 不跨境=不经过出口；诚实接受 |
| 系统层强指纹 | MAC/SMBIOS/显卡指纹等本地可读项 | 收紧权限（日常不提权）；威胁模型一般够不到（需本地执行权） |
| 输入法词库/浏览历史 | 应用内数据，配置层无解 | 云同步关闭；输入法语义是行为信号，归入"服务商侧聚合"缓解 |

## 三、判定机制残余（误差不等于漏洞，但要知道方向）

| 残余 | 说明 |
|---|---|
| GeoSite/GeoIP 名单制判定 | 漏收的境外域被误判"国内"→ 直连暴露（方向安全）；错收进 cn 组的境外域 → 该域直连（极低概率，巡检可捕捉异常）。名单质量高但无理论保证 |
| killswitch 名单外应用 | 误关代理时无 fail-closed 保护，依赖"TUN 常开"纪律。加名单的判据 = 裸连伤害 >> 暂时断连不便 |
| 进程白名单的国内应用 | 白名单进程内嵌的第三方 SDK 与其宿主共享直连通道（微信里的浏览器内核访问了什么都走微信的白名单）——白名单按"最小化+逐条理由"维护是唯一的闸 |

## 四、体系外威胁（任何民用方案无解）

- **恶意驱动/rootkit/供应链植入**：内核级恶意组件可绕过一切配置层防护。防线只有一条：不装来路不明的软件、系统补丁及时。
- **物理/执法层面**：设备被直接取证不在本体系范围。
- **对方人工社工**：你的公开言行、社交关系与掩护身份矛盾时，任何技术层都救不回来。

## 使用本清单的姿势

1. 每次新装软件/新注册账号前，过一遍§三：它会落在哪个残余面上？
2. 巡检报告出现 FAIL 时，先对照本清单确认它是不是"已知残余被误报"，再决定修复动作。
3. 本清单随实践更新——每发现一个新的"做不到"，加一行。清单越长，体系越诚实。
