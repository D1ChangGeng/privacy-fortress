# 事故录与决策记录

变更只进这里：每个重大决策的"当时发生了什么、选了什么、为什么"。规范文档描述最终状态，本文保留推理链，供"当时为什么这样定"的追溯与同类事故的提前识别。日期均为当地时间。

## DNS 子系统

**系统 DNS 客户端文件损坏（2026-09-27）**
症状：DNS Client 服务因系统文件缺失无法启动，全机任何网络形态（网线/USB/蓝牙）均不可用，所有修复路径无效，最终重装系统。
决策：此后每个施工阶段强制"回退脚本先行 + 超时自动回退防线"——系统可用性优先级高于一切隐私目标；任何"可能有多种可选路径或不同风险"的策略不再停下等确认，而是预置回退后连续执行。
教训：**系统级组件（DNS Client/TUN/防火墙）没有"半坏"状态，只有"好"和"全断"**。对它们的每次修改都要按"改完可能开不了机"来预案。

**校园网关劫持 UDP53（2026-10-19 发现，v1.38 根治）**
症状：ipleak DNS 检测出现大量中国联通递归解析器（v4 27.40.x 族 / v6 2408:8201 族）与 Cloudflare 东京混合；`www.google.com` 被解析到 Facebook 的 IP（投毒实锤）。
根因：内核用明文 `223.5.5.5`（UDP 53）解析境外域名，该流量按 GEOIP 走 DIRECT 出本地网，被校园 Panabit 设备整体代答——无论查询目标是哪个公共 DNS。境外浏览记录经运营商递归暴露，且应答可被任意改写。
决策：非 CN 域名解析全部改 DoH-over-proxy（`https://1.1.1.1/dns-query` + `https://8.8.8.8/dns-query`，IP 字面量免引导），DoH 流量按规则进代理链；CN 域名保留国内 DNS 直连（国内人设折衷）。验证口径：ipleak dnsdetection 官方 API 脚本化检测，解析器必须全部落在 Cloudflare/Google/Quad9 白名单段——已固化为每日巡检哨兵。
教训：**明文 53 端口在不可信本地网上没有任何目的地可言**。选住宅 IP 时增加一条验收：该网络环境的网关是否劫持 UDP53（高校/酒店/企业网常见）。

**本地 DNS 转发器退役（2026-10 演进）**
早期方案：核心 nameserver 首查 127.0.0.1:53 本地转发器 → 转发器做 DoH。退役原因：多一跳本地组件；回环 53 单端口在部分客户端配置通道被拒（实测仅 53 被拒、非防火墙）；无消费者后纯属攻击面。现架构：核心直出 DoH-over-proxy（见 proxy-dns-architecture.md §2）。旧脚本 `scripts/dns-forwarder.py` 存档保留，供无法接受 DoH nameserver 的旧客户端形态参考。

## 拦截工具选型

**进程级防火墙（Portmaster 类）弃用（2026-09-28）**
症状：安装后整机断网（其自身 DNS 层与网关 TUN 互抢），卸载后仍有配置残留影响连通。
决策：拦截与分流回归网关规则 + Windows 防火墙 killswitch 两层。教训：**不要叠加两个都想接管全机流量的中间层**——同一层只能有一个所有者。

**沙盒（Sandboxie 类）弃用（2026-09-27/28）**
症状：国产视频应用沙盒内黑屏无法使用；注册表/文件层阻断可被沙盒内测试绕过，防护承诺与实态不符。
决策：放弃"把不可信应用关进笼子"路线，改"允许采集、采集面缺失"——应用照常跑，但它能采到的全是掩护面。教训：**与应用兼容性正面冲突的防护层不可持续**，用户会为了用应用而拆防护；设计时先评估目标应用集的兼容性。

**CCleaner 类清理工具移除（2026-09-26）**
清理工具拥有最高文件可见性，是采集面而非防护面——它在扫描时读完你所有的浏览器痕迹、文档名、软件列表再决定"清不清"。处置：卸载+残留清理；系统层防护由本体系各组件承担。

**国产管家/自保护组件（Lenovo PC Manager 等，2026-09-26）**
症状：服务无法常规停用（Access denied），卸载需重启生效。
决策：按 system-signals.md"允许采集、采集面缺失"原则处置，不与其自我保护机制正面对抗；确实要卸的服务走"停服务→卸载→重启验证"三步，卸载失败残留记入台账择机处理。

## 客户端与配置治理

**GUI 客户端升级回写直改（2026-10-17，两次实战）**
两次客户端大版本升级：① 自建链式节点被删除、引用它的规则被全局改名指向底层组（链断，全部流量绕过住宅层）；② 此前所有文件直改的规则编辑被回滚。另有：手工 INSERT 的数据库规则行字段与 UI 行完全一致也不被消费（UI 通道有独立状态校验）。
决策：主形态迁移到自建裸网关（配置即真源）；GUI 客户端降级为回退备胎，且一切编辑走 UI 编辑器、升级前备份三件套、升级后四键核验。规则新增必须走 UI——这条写进了 network-gateway.md §5。

**双实例静默半死（2026-10-19）**
症状：配置 DNS 修复重启时，旧内核进程由 highest 权限计划任务启动、普通会话杀不掉；非提权启动的新实例抢不到端口与 TUN，静默半死——面板在、规则在、TUN 没接管。
决策：重启脚本统一提权（UAC 一次）+ 启动幂等（已运行跳过）+ 发现双开全杀后单实例启动。写入 ops-runbook.md 双开处置。

**遥测域名拦截语义事故（2026-09-28）**
REJECT（拦截=断其网且应用报错）与 MATCH（引流=送链让应用以为连上了）被混用，导致目标 AI 应用反复重连失败。
决策：语义写进纪律——**引流优先于拦截；拦截只用于纯遥测域名**（应用拿不到会降级的诊断/统计域）；对"必须连上才工作"的端点一律 MATCH 或 DIRECT。REJECT 相位仍在五相位之首（遥测先掐），但新增 REJECT 条目必须过"应用失去它能否正常工作"的测试。

**进程名漂移（2026-10-17 前后）**
症状：客户端升级后进程名改变，旧进程白名单规则失效（表现为"应用突然走链了"或"应用连不上"）。
决策：进程规则用全路径（`PROCESS-PATH`）优先于纯名字（`PROCESS-NAME`）；`find-process-mode: strict` 保证 TUN 下进程识别可用；白名单进程表入台账，升级后核对。

## 服务侧处置

**Tailscale 自报家门（2026-09-26）**
症状：审计同时出现"东京出口"与"广东端点"两条记录——Tailscale 守护进程在本地记录真实公网端点，任何能读其状态/日志的本地程序绕过所有网络层直接拿到真实位置。
决策：按 system-signals.md VPN 客户端二选一处置（本文记录时为"用完即停+手动启动"方案）。同时确立同类排查法：**盘点机器上所有 VPN/远控/mesh 客户端**——它们都是协议级自报家门源，服务商侧永远知道你的真实 IP（协议决定），防护目标只能是"本机其他应用读不到"。

**账号注册资料与登录时机（2026-09-30）**
决策：登录任何境外 AI 服务前，先核对账号邮箱/手机/支付国别与掩护画像一致（东京），再登录。登录后再补资料会留下"注册地X、首次登录地Y"的交叉信号。
